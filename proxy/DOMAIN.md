# Бесплатный домен для Cloudflare — пошаговый комплект

> **Сначала важное.** Домен для работы прокси **не нужен**: адрес
> `https://cf-proxy.<логин>.workers.dev` уже бесплатный и открывается из РФ.
> Этот документ — если вы хотите красивый свой адрес (`myproxy.eu.org`).

Я не могу зарегистрировать домен за вас: регистрация требует **вашего e-mail**
(на него приходит подтверждение), ваших данных и ручного одобрения модератором,
а привязка — входа в **ваш** аккаунт Cloudflare. Но всё остальное я автоматизировал:
скрипт `tools/cf-domain.mjs` делает часть Cloudflare через API.

**Порядок важен:** сначала Cloudflare (он выдаёт NS), потом eu.org (вписываете эти NS).

---

## Шаг 0. Подготовка (5 минут, один раз)

1. **Аккаунт Cloudflare** — <https://dash.cloudflare.com/sign-up> (бесплатно, без карты).
2. **API-токен**: панель → *My Profile → API Tokens → Create Token → Custom token*.
   Права: **Zone → Edit** и **Account → Workers Scripts → Edit**. Скопируйте токен.
3. **Account ID**: правый сайдбар на главной панели (или *Workers & Pages → Overview*).
4. Положите в переменные окружения (PowerShell):

```powershell
$env:CF_API_TOKEN  = "<ваш токен>"
$env:CF_ACCOUNT_ID = "<ваш account id>"
$env:DOMAIN        = "myproxy.eu.org"     # желаемое имя
$env:WORKER_NAME   = "cf-proxy"
```

---

## Шаг 1. Создать зону в Cloudflare и получить NS

```bash
node tools/cf-domain.mjs create-zone
```

Скрипт создаст зону и **напечатает два NS-сервера** вида
`dana.ns.cloudflare.com` / `rob.ns.cloudflare.com`. **Сохраните их** — они нужны на шаге 2.

Пока статус зоны будет `pending` — это нормально, он станет `active` после eu.org.

---

## Шаг 2. Заявка на бесплатный домен eu.org

**eu.org** — некоммерческий проект с 1996 года, даёт `имя.eu.org` бесплатно и
навсегда, позволяет менять NS. Это самый надёжный бесплатный вариант (переживёт
большинство коммерческих сервисов).

1. Откройте <https://nic.eu.org> → **Sign up / Register**.
2. Заполните: логин, **реальный e-mail** (на него придёт активация и результат),
   имя, страна, город. Нажмите **Create**.
3. Письмо с ссылкой активации → перейдите по ней → войдите в панель.
4. **New domain** → введите домен (например `myproxy.eu.org`).
5. В разделе **Name servers** укажите **оба NS из шага 1** (именно они, не другие).
6. **Submit**. Дальше — ожидание ручной проверки: обычно **от нескольких дней до 2–3 недель**.

### Готовый текст заявки (можно скопировать)

```
Domain requested:  myproxy.eu.org
Purpose:           personal developer proxy / API gateway
Name servers:
  <NS-1 из шага 1>
  <NS-2 из шага 1>
Owner:             <ваше имя>
Email:             <ваш e-mail>
Country:           <ваша страна>
```

> Модератор смотрит, чтобы данные были правдоподобными и e-mail рабочим.
> Не выдумывайте адрес почты — на него приходит результат.

### Альтернативы, если не хотите ждать eu.org

| Провайдер | Домен | Скорость | NS → Cloudflare |
|---|---|---|---|
| **us.kg** | `имя.us.kg` | часы | да |
| **pp.ua** | `имя.pp.ua` | дни (нужен телефон) | да |
| **CloudDNS** | `имя.cloud-ip.cc` | мгновенно | **нет** (в CF не заведёте) |

Порядок тот же: сначала `create-zone` → потом NS в панель провайдера.

---

## Шаг 3. Проверить, что зона стала активной

Через несколько часов (иногда до суток) после одобрения:

```bash
node tools/cf-domain.mjs status
```

Ждём `Статус: active`. Если всё ещё `pending` — NS ещё не разошлись, подождите.

---

## Шаг 4. Привязать домен к воркеру

```bash
node tools/cf-domain.mjs attach
```

Скрипт повесит `myproxy.eu.org` на воркер `cf-proxy`. SSL-сертификат Cloudflare
выпустит сам за 1–5 минут.

Проверка:

```bash
curl https://myproxy.eu.org/health
```

Должен вернуться JSON со `"ok": true`.

---

## Шаг 5 (опционально). Управление

```bash
node tools/cf-domain.mjs list-domains     # все кастомные домены аккаунта
node tools/cf-domain.mjs delete-domain    # отвязать домен от воркера
```

Домен при этом остаётся за вами — отвязывается только маршрут к воркеру.

---

## Частые проблемы

| Симптом | Причина / решение |
|---|---|
| `status` всё время `pending` | NS в eu.org не совпадают с выданными Cloudflare. Сверьте посимвольно |
| `attach` → `zone not active` | Дождитесь одобрения eu.org; зона активируется только после подтверждения NS |
| `Cloudflare API 403` | У токена нет прав **Zone:Edit** или **Workers:Edit** — пересоздайте токен |
| Домен открывается, но 522 | Воркер не задеплоен или DNS-запись proxied мешает. Проверьте `wrangler deploy` |
| Хочу и `workers.dev`, и свой домен | Можно: они работают одновременно |

## Итог

- **Без домена:** `https://cf-proxy.<логин>.workers.dev` — уже работает, 0 действий.
- **Со своим доменом:** 4 шага выше, из них «ручных» — только регистрация на eu.org
  (ваш e-mail) и один прогон скрипта на каждом этапе.
