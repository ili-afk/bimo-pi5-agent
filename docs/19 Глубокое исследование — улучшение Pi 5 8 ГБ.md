# 19. Глубокое исследование — как улучшить Pi 5 8 ГБ, не покупая 16 ГБ

**Дата:** 08.10.2026
**Задача:** поднять возможности Raspberry Pi 5 **8 ГБ** без покупки версии на 16 ГБ (которая вдвое дороже: 30 000 ₽ против 15 000 ₽).
**Метод:** измеренные бенчмарки, официальная документация Raspberry Pi и Hailo, гайды по оптимизации llama.cpp, живой рынок Авито.

---

## 0. TL;DR — карта рычагов

| # | Рычаг | Эффект | Цена | Сложность |
|---|---|---|---|---|
| 1 | **Правильная модель** (Gemma 3n E4B, Qwen3-4B) | 8B-класс в **4 ГБ** вместо 5,2 ГБ | 0 ₽ | низкая |
| 2 | **Квантизация + KV-кэш** (`-ctk q8_0`) | −30…50 % на кэш контекста | 0 ₽ | низкая |
| 3 | **Слим-профиль ОС** | **+2,1 ГБ** свободной RAM | 0 ₽ | средняя |
| 4 | **Флаги llama.cpp** | +5…15 % промпта | 0 ₽ | низкая |
| 5 | **Разгрузка** (ASR/TTS/мозг) | +1,3 ГБ | 0 ₽ | средняя |
| 6 | **Разгон 2,8 ГГц** | +5,9 % промпта, **+0,9 % генерации** | 0 ₽ | средняя |
| 7 | **AI HAT+ 2** (Hailo-10H) | +8 ГБ своей RAM, **×5,5 к скорости** | 25 500 ₽ | высокая |
| 8 | **llama.cpp RPC** с ПК | RAM большого ПК как своя | 0 ₽ | высокая |

**Главный вывод исследования:**

> **Генерация токенов на Pi 5 упирается не в процессор, а в пропускную способность памяти.**
> При разгоне с 2,6 до 2,8 ГГц обработка промпта ускорилась на **5,9 %**, а генерация — всего на **0,9 %**.
> Поэтому «улучшить плату» разгоном почти нельзя. Улучшать надо **объём данных, которые прокачиваются через шину** — то есть модель, её квантизацию и кэш.

**И ещё важное:** на 8 ГБ **уже работает 8B-модель**. Измерено: Qwen3-8B Q4_K_M (4,68 ГиБ) → 5,2 ГБ занято из 7,87 ГБ, **2,67 ГБ запаса**, 2,15 ток/с, 55 °C, без троттлинга. Так что задача не «влезет ли 8B», а «как сделать это быстрее и с запасом».

## 1. Измеренная картина: где именно узкое место

### 1.1 Что реально занимает память

Замер на Pi 5 8 ГБ, модель Qwen3-8B Q4_K_M, `llama-server`, 4 потока, контекст 4096:

| Параметр | Значение |
|---|---|
| Видно памяти Linux | 7,87 ГБ |
| Размер GGUF-файла | 4,68 ГиБ |
| Занято всего (модель + рантайм + ОС) | 5,2 ГБ |
| Свободный запас | **2,67 ГБ** |
| Температура | ~55 °C |
| `get_throttled` | 0x0 (без троттлинга) |
| Скорость генерации | 2,15 ток/с |

**Вывод:** файл модели — это **не** весь бюджет. Оставшиеся ~0,5 ГБ сверх файла — это KV-кэш, вычислительные буферы и ОС. Контекст 4096 — разумный баланс; 8192 влезет, но съест запас безопасности.

### 1.2 Разгон: почему он почти не помогает

| Частота | Обработка промпта | Генерация |
|---|---|---|
| 2,6 ГГц | 10,56 ток/с | 2,13 ток/с |
| 2,8 ГГц | 11,18 ток/с (**+5,9 %**) | 2,15 ток/с (**+0,9 %**) |
| 3,0 ГГц (llama-bench, pp128/tg128) | 11,45–11,50 | 2,30–2,45 |

Формулировка из самого исследования: *«Узкое место смещается: сначала вычисления, потом память, потом терпение»*.

**Механика:** LPDDR4X-4267 даёт 34 ГБ/с. Чтобы сгенерировать один токен, нужно прогнать через шину все активные веса модели. Для 8B Q4 это ~4,7 ГБ на каждый токен. При 34 ГБ/с теоретический потолок ≈ 7 ток/с; реальные 2,15 ток/с — следствие того, что память делится с ОС и другими процессами. **Частота ядра здесь ни при чём.**

**Практический вывод:** разгон стоит делать (он бесплатный и даёт +6 % на промпте, что заметно при длинных запросах), но **не ждите от него роста генерации**. Если нужна скорость генерации — уменьшайте объём модели, а не увеличивайте частоту.

## 2. Рычаг 1 — Правильная модель (0 ₽, максимальный эффект)

### 2.1 Модели, которые дают «больше» при меньшем объёме

**Gemma 3n — главная находка.** Google сделала её специально для устройств с малой памятью: за счёт MatFormer и разделяемого KV-кэша модель с реальными **5B / 8B** параметров требует всего **2 ГБ / 4 ГБ**.

| Вариант | Реальных параметров | Требует памяти | Влезает в 8 ГБ? |
|---|---|---|---|
| Gemma 3n **E2B** | 5B | ~2 ГБ | да, с огромным запасом |
| Gemma 3n **E4B** | **8B** | **~4 ГБ** | **да, с запасом ~2,5 ГБ** |

То есть **8B-класс за 4 ГБ** вместо 5,2 ГБ у Llama 3 8B. Это ровно то, что нужно: больше качества — меньше памяти. Плюс Gemma 3n мультимодальна (умеет картинки), что для BIMO с камерой бонус.

### 2.2 Полная таблица выбора

| Модель | Память (Q4) | MMLU | Сильная сторона | Скорость на Pi 5 (оценка) |
|---|---|---|---|---|
| **Gemma 3n E4B** | ~4,0 ГБ | 8B-класс | Баланс качества и памяти, мультимодальность | ~2,5–3 ток/с |
| **Qwen3-4B** | ~2,5 ГБ | **73,0** | Лучшее качество на единицу памяти | ~3 ток/с |
| Qwen3-1.7B | 1,79 ГБ | 62,6 | Быстрая, умная для своего размера | ~4,8 ток/с |
| Llama 3.2 3B | 2,4 ГБ | 63,4 | **77,4 IFEval** — лучшее следование инструкциям | ~5 ток/с |
| **BitNet b1.58 2B4T** | **1,2 ГБ** | — | **Измерено на Pi 5: 6,43 ток/с** | **6,4 ток/с** |
| DeepSeek-R1-Distill-Qwen-1.5B | 1,3 ГБ | — | **83,9 MATH-500** — математика и reasoning | ~6,8 ток/с |
| Qwen2.5-Coder-1.5B | 1,3 ГБ | — | **70,7 HumanEval** — код | ~7,9 ток/с |
| Qwen2-1.5B | 1,3 ГБ | 41,2 | Устарела, не брать | ~5,5 ток/с |

**Ключевое наблюдение:** Qwen3-1.7B (2025) набирает 62,6 MMLU, а Qwen2-1.5B (2024) — 41,2. При почти одинаковом размере. **Поколение модели важнее её размера.** Qwen3-4B (2,5 ГБ, MMLU 73,0) обгоняет Llama 3 8B (5,2 ГБ, MMLU 66,6) при вдвое меньшей памяти.

### 2.3 BitNet — измеренный результат на Pi 5

BitNet b1.58 2B4T (Microsoft) — 1,58-битная модель, запускается через `bitnet.cpp`. Реальный замер на Pi 5 8 ГБ:

| Метрика | Значение |
|---|---|
| Размер модели | **1,2 ГБ** |
| Время загрузки | 953 мс |
| Обработка промпта | 5,57 ток/с |
| **Генерация** | **6,43 ток/с** |
| Потребление | ниже обычного llama.cpp (меньше вычислений) |

Для сравнения: Qwen3-8B Q4_K_M — 2,15 ток/с при 4,68 ГиБ. **BitNet втрое быстрее при вчетверо меньшем размере.** Качество ниже, но для голосового ассистента, где ответ нужен быстро, это сильный вариант.

Сборка требует Clang 18 и виртуального окружения; полный процесс задокументирован в гайде Adafruit, проверен на Pi 4 и Pi 5.

## 3. Рычаг 2 — Квантизация и KV-кэш (0 ₽)

### 3.1 Выбор квантизации

| Квантизация | Размер 8B | Качество | Комментарий |
|---|---|---|---|
| Q8_0 | ~8,5 ГБ | эталон | не влезет |
| Q5_K_M | ~5,7 ГБ | очень высокое | впритык, риск OOM |
| **Q4_K_M** | **4,68 ГиБ** | **хорошее** | **рекомендуемый баланс** |
| Q4_0 | ~4,3 ГБ | чуть ниже | быстрее грузится, для hailo-ollama |
| IQ4_XS | ~4,1 ГБ | ≈ Q4_K_M | экономия ~0,5 ГБ почти бесплатно |
| Q3_K_M | ~3,7 ГБ | заметная просадка | когда нужен запас |
| IQ2_XXS | ~2,2 ГБ | сильная просадка | крайний случай |

**Практика:** начните с **Q4_K_M**; если не хватает запаса — переходите на **IQ4_XS** (то же качество, −0,5 ГБ), а не сразу на Q3.

### 3.2 KV-кэш — недооценённый резерв

KV-кэш растёт **линейно** с длиной контекста и может съесть больше, чем сама модель на длинных диалогах. Квантизация кэша — самый дешёвый способ это обуздать.

| Флаг | Что делает | Экономия |
|---|---|---|
| `-ctk q8_0 -ctv q8_0` | ключи и значения в 8 бит | **~50 %** размера кэша |
| `-ctk q4_0 -ctv q4_0` | в 4 бита | ~75 % (заметная потеря качества) |
| `-c 2048` вместо `8192` | короче контекст | пропорционально |

**Готовая команда для Pi 5 8 ГБ:**

```
./build/bin/llama-server \
  -m /srv/models/Qwen3-4B-Q4_K_M.gguf \
  -t 4 -c 4096 -np 1 \
  -ctk q8_0 -ctv q8_0 \
  --host 127.0.0.1 --port 8080
```

Проверяйте фактический расход через `Maximum resident set size`:

```
/usr/bin/time -v ./build/bin/llama-cli -m model.gguf -p "тест" -n 128 -t 4 -c 4096
```

## 4. Рычаг 3 — Флаги и сборка llama.cpp (0 ₽)

### 4.1 Сборка

| Вариант | Команда | Что даёт |
|---|---|---|
| Базовая | `cmake -B build -DCMAKE_BUILD_TYPE=Release` | эталон |
| **Native** | `cmake -S . -B build-native -DCMAKE_BUILD_TYPE=Release -DGGML_NATIVE=ON` | оптимизация под конкретный CPU |
| OpenBLAS | `-DGGML_BLAS=ON -DGGML_BLAS_VENDOR=OpenBLAS` | **только промпт**, генерацию не ускоряет |

Важно: нативный бинарник **не переносится** на другой ARM-процессор. Замеряйте против базовой сборки, а не верьте на слово.

### 4.2 Runtime-параметры

| Параметр | Что контролирует | С чего начать |
|---|---|---|
| `-t, --threads` | потоки для генерации | проверить 1, 2 и 4 — **больше не всегда быстрее** |
| `-c, --ctx-size` | размер KV-кэша | 2048, увеличивать только при нужде |
| `-b, --batch-size` | размер батча промпта | по умолчанию, потом замерять |
| `-np 1` | параллельные слоты | **1** — иначе память умножается |
| `--load-mode mmap+mlock` | зафиксировать модель в RAM | только если всё влезает |
| `--load-mode none` | без mmap и без лока | только по измеренной причине |

**Про `mlock`:** в текущих сборках это `--load-mode mmap+mlock`, в старых — `--mlock`. Смысл — запретить ядру выгружать модель в своп. **Ускорения вычислений он не даёт**, только устраняет паузы при нехватке памяти. Использовать только когда модель целиком помещается в RAM. Лимит проверяется через `ulimit -l`; для systemd задаётся явно:

```
[Service]
LimitMEMLOCK=6G
```

### 4.3 Замеры

```
./build/bin/llama-bench -m model.gguf -p 512 -n 128 -t 1,2,4 -r 5 -o md
```

`llama-bench` показывает промпт (pp) и генерацию (tg) отдельно. Не сравнивайте холодный первый прогон с прогретым повтором.

## 5. Рычаг 4 — Слим-профиль ОС (0 ₽, +2,1 ГБ)

Самый недооценённый рычаг: он бесплатный и освобождает больше памяти, чем любая настройка модели.

| Компонент | Как обычно | Слим-профиль | Экономия |
|---|---|---|---|
| ОС | Raspberry Pi OS **Desktop** | Raspberry Pi OS **Lite** | −0,6 ГБ |
| ASR | faster-whisper **small** (1,25 ГБ) | **whisper.cpp base/tiny** (0,2 ГБ) | −1,0 ГБ |
| TTS | Piper (0,3 ГБ) | **edge-tts** (облако, 0,05 ГБ) | −0,25 ГБ |
| Wake word + VAD | 0,3 ГБ | openWakeWord + Silero (0,15 ГБ) | −0,15 ГБ |
| Шлюз + SQLite | 0,5 ГБ | без изменений | 0 |
| **Инфраструктура итого** | **~3,4 ГБ** | **~1,3 ГБ** | **−2,1 ГБ** |

**Было:** на модель остаётся 3,5–5,5 ГБ → только 3B.
**Стало:** **~6,5 ГБ** → влезает Gemma 3n E4B (8B-класс) **и остаётся 2,5 ГБ запаса**.

### 5.1 zram: важное предупреждение

**zram НЕ поможет запустить модель крупнее.** Причина: веса модели уже сжаты квантизацией, и они «несжимаемы» — коэффициент сжатия для них близок к 1:1, то есть вы тратите CPU и не получаете памяти. В гайде это прямо отмечено: для несжимаемых данных — «маленький тест или вообще без zram».

**Где zram реально помогает:** ОС, файловый кэш, страницы Python-рантайма — то есть всё сжимаемое. Это даёт больше отзывчивости при пиках, но не увеличивает бюджет модели.

Если всё же включать:

```
# Вариант 1 — zram-tools
sudo apt install zram-tools
# /etc/default/zramswap
ALGO=lz4
PERCENT=50
PRIORITY=100
```

```
# Вариант 2 — systemd-zram-generator
# /etc/systemd/zram-generator.conf
[zram0]
zram-size = min(ram / 2, 2048)
compression-algorithm = lz4
swap-priority = 100
```

**Не запускайте оба менеджера одновременно** — они конфликтуют за `/dev/zram0`. `PERCENT=50` задаёт максимальную ёмкость устройства, а не резервирует половину RAM сразу.

### 5.2 swap на NVMe: только страховка

Правило из гайда: *«Не прячьте проблему OOM, добавляя много медленного свопа»*.

Своп на NVMe нужен, чтобы система не упала, а не чтобы работать быстрее. Напоминание: LPDDR4X — 34 ГБ/с, NVMe через PCIe 2.0 x1 — ~450 МБ/с. При активном свопе производительность падает в десятки раз. **Правильное действие при нехватке памяти — уменьшить модель или контекст, а не наращивать своп.**

## 6. Рычаг 5 — Разгрузка (0 ₽)

| Что | Куда | Экономия на Pi |
|---|---|---|
| ASR | облако (Groq Whisper) или whisper.cpp base | 0,7–1,2 ГБ |
| TTS | edge-tts (облако, бесплатно) | 0,25 ГБ |
| Wake word + VAD | сопроцессор ESP32 | 0,15 ГБ + сон Pi |
| Тяжёлый LLM | ПК через Ollama или llama.cpp RPC | вся модель |
| Генерация 3D | облако (Meshy / Tripo / Rodin) | 0 |

**llama.cpp RPC — самый интересный приём:** на ПК запускается `rpc-server`, на Pi — клиент с `--rpc`. Модель распределяется между машинами, и Pi буквально использует RAM ПК как продолжение своей. Ограничение — сеть: у Pi 5 гигабитный Ethernet (~110 МБ/с реально), поэтому для больших моделей это работает по схеме layer-split, но не tensor-parallel. Для дома это лучший способ получить 14B+ без покупки железа.

## 7. Рычаг 6 — Разгон (0 ₽, но эффект ограничен)

**Стабильный ежедневный профиль — 2,8 ГГц** (55 °C, `get_throttled=0x0`). Путь к 3,0 ГГц — только после длительного soak-теста.

```
# /boot/firmware/config.txt
[all]
over_voltage_delta=50000
arm_freq=3000
```

**Чего НЕ делать:**
- Не добавлять `gpu_freq=1000` — модель считается на CPU-ядрах, прироста для llama.cpp нет, только новая переменная стабильности.
- Не использовать `force_turbo=1` — пусть частота и напряжение падают в простое.
- Не тестировать рискованную частоту без бэкапа `config.txt`.

**Обязательная процедура:**

```
sudo cp /boot/firmware/config.txt /boot/firmware/config.txt.bak
# ... правки ...
sudo reboot
vcgencmd get_config arm_freq
vcgencmd get_throttled
```

```
sudo apt install stress-ng
stress-ng --cpu 4 --cpu-method matrixprod --verify --timeout 30m --metrics-brief
```

Мониторинг во время тестов:

```
watch -n 1 'vcgencmd measure_clock arm; vcgencmd measure_temp; vcgencmd get_throttled; free -h'
```

**Реалистичное ожидание:** +5,9 % на обработке промпта, +0,9 % на генерации. Разгон оправдан, потому что бесплатный, но он **не** решает главную задачу.

## 8. Рычаг 7 — AI HAT+ 2 (25 500 ₽, ×5,5 к скорости)

### 8.1 Критично: не купите не ту плату

| Плата | Ускоритель | TOPS | Своя память | **LLM?** | Цена в РФ |
|---|---|---|---|---|---|
| AI Kit / AI HAT+ (13 TOPS) | Hailo-8L | 13 INT8 | нет | **НЕТ** | 6 500–7 000 ₽ |
| AI HAT+ (26 TOPS) | Hailo-8 | 26 INT8 | нет | **НЕТ** | 16 800 ₽ |
| **AI HAT+ 2** | **Hailo-10H** | **40 INT4** | **8 ГБ** | **ДА** | **25 500 ₽** |

**Дешёвые платы за 6 500–16 800 ₽ работают только с компьютерным зрением.** Языковые модели они не запускают — это разные ускорители и разные программные пакеты (`hailo-all` против `hailo-h10-all`, они **не могут сосуществовать** в системе).

### 8.2 Что даёт

| Модель на Hailo-10H | Память | Скорость | MMLU |
|---|---|---|---|
| Phi-2 (2,7B) | 2,8 ГБ | **19 ток/с** | 56,7 |
| **Llama 3 8B** | 5,2 ГБ | **11 ток/с** | 66,6 |
| Llama 2 7B | 4,8 ГБ | 10 ток/с | 45,3 |
| Qwen2-1.5B | 1,2 ГБ | 9,45 ток/с | 41,2 |
| Qwen3-1.7B | 1,79 ГБ | 4,78 ток/с | 62,6 |
| Llama 3.2 3B | 2,4 ГБ | 2,65 ток/с | 63,4 |

**Против CPU Pi 5:** Llama 3 8B — 11 ток/с против ~2. Ускорение **×5,5**. Энергоэффективность **~4,5 ток/с на ватт** (против ~0,5 у CPU).

Ключевое: **8 ГБ находятся на самой плате и не занимают RAM Raspberry Pi.** То есть Pi 5 8 ГБ сохраняет свои 8 ГБ под ОС, ASR, TTS, шлюз — и всё это работает параллельно с моделью. По эффективной архитектуре это «8 + 8 ГБ», но с NPU вместо медленного CPU.

**Не форсируйте PCIe Gen 3** — для AI HAT+ 2 это делается автоматически (в отличие от старого AI Kit).

### 8.4 Ограничения, которые надо принять

- **Только модели, скомпилированные Hailo.** Произвольный GGUF или чекпойнт с Hugging Face напрямую не переносится: *«a generic GGUF or Hugging Face checkpoint cannot be copied directly to the Hailo-10H»*.
- Обходной путь — `hailo-ollama` (прогоняет GGUF Q4_0 через Hailo с небольшой потерей производительности), но список всё равно ограничен.
- **Занимает единственную линию PCIe** → NVMe одновременно невозможен, SSD только через USB 3.0.
- CPU Pi 5 всё равно работает: ОС, API, интерфейс, пре/постобработка.
- Производитель прямо советует ставить радиатор под интенсивные нагрузки; рабочая температура 0…+50 °C.

## 9. Что НЕ работает (проверено)

| Идея | Почему не работает |
|---|---|
| **Докупить RAM** | LPDDR4X распаяна по PoP. Слота нет. Только покупка другой платы |
| **zram для модели** | Веса уже сжаты квантизацией, коэффициент сжатия ≈ 1:1. Тратите CPU, памяти не получаете |
| **Своп на NVMe как рабочая память** | 450 МБ/с против 34 ГБ/с → падение в ~75 раз. Вместо 2 ток/с получите 0,3–1 |
| **Разгон для генерации** | Генерация memory-bound: +0,9 % при +200 МГц. Помогает только промпту |
| **Кластер из двух Pi 5** | Сеть 1 Гбит/с (~110 МБ/с) — слишком медленно для обмена тензорами. Не даёт «16 ГБ» |
| **AI HAT+ / AI Kit за 6 500–16 800 ₽** | Hailo-8L и Hailo-8 не поддерживают LLM, только CV |
| **MemryX MX3 (M.2)** | Нужно **2 линии PCIe** Gen3 (у Pi 5 — одна), 13–14,85 Вт, ориентирован на видеопоток. Не подходит |
| **Квантование Q5/Q8 ради скорости** | Наоборот: больше объём → больше трафик через шину → медленнее |

## 11. Рекомендуемая последовательность

**Шаг 1 — бесплатно, сразу (даёт больше всего):**
1. Raspberry Pi OS **Lite** вместо Desktop.
2. ASR → **whisper.cpp base**, TTS → **edge-tts**.
3. Модель → **Gemma 3n E4B** или **Qwen3-4B**.
4. `-ctk q8_0 -ctv q8_0 -c 4096 -np 1 -t 4`.
5. Сборка с `-DGGML_NATIVE=ON`.

Итог: **8B-класс в 8 ГБ с запасом 2,5 ГБ**, скорость ~3 ток/с, вся инфраструктура BIMO работает параллельно.

**Шаг 2 — бесплатно, если нужна скорость:**
6. Разгон до 2,8 ГГц (с бэкапом и stress-тестом).
7. Мозг на ПК через Ollama/RPC для сложных запросов.
8. BitNet b1.58, если ответ нужен максимально быстро.

**Шаг 3 — платно, если всё ещё мало:**
9. **AI HAT+ 2** за 25 500 ₽ → Llama 3 8B на 11 ток/с, +8 ГБ своей памяти. Не покупать M.2 HAT, SSD — через USB 3.0.

**Чего не делать:** покупать Pi 5 16 ГБ (+15 000 ₽) ради скорости — CPU остаётся тем же, а 16 ГБ имеет смысл только под объём (много параллельных агентов, векторная БД, Docker).
