## 0. TL;DR

| Вопрос | Ответ |
|---|---|
| Убрать локальную модель, считать в облаке? | **Да — и это лучший вариант.** Проблема 8 ГБ исчезает полностью |
| Можно ли подключить именно «модель от WorkBuddy AI»? | Само приложение WorkBuddy AI публичного API не отдаёт. **Но на этой машине уже есть `vibe-proxy` на порту 8317** — OpenAI-совместимый шлюз с NVIDIA 120B/550B, Claude Sonnet 4.5, Gemini |
| Нужен ли VPN? | **Скорее всего НЕТ.** Ваш же документ `GEO-BLOCKING.md` фиксирует: ваш Cloudflare-воркер отдаёт **200 и с VPN, и без него**. VPN нужен только для прямого NVIDIA-эндпоинта |
| Ставить VPN на Pi 5? | **Не надо.** Держите выход на ПК — Pi остаётся чистым |
| Pi 5 как процессор и RAM? | Процессор и RAM для модели — в датацентре NVIDIA. Pi делает ASR/TTS/шлюз, и ему хватает **1–2,8 ГБ** из 8 |
| SD-карта на 128 ГБ? | Ёмкости с запасом. **Но главный риск — износ карты**, а не место |

**Итог:** архитектура «тонкий клиент + облачный мозг» снимает задачу «как всунуть модель в 8 ГБ» целиком. Pi 5 перестаёт быть вычислителем для модели и становится голосовым интерфейсом.

## 2. Про VPN: три варианта, и лучший — без VPN на Pi

| Вариант | Как | Плюсы | Минусы |
|---|---|---|---|
| **A. Шлюз на ПК (рекомендую)** | Pi → ПК по LAN/Tailscale → vibe-proxy сам выбирает выход | Pi вообще без VPN; вся логика гео-обхода уже написана; один раз настроить | ПК должен быть включён |
| **B. Прямо в Cloudflare-воркер** | Pi → `nvidia-api-proxy...workers.dev` | ПК не нужен; работает из РФ **без VPN**; 82 модели | нет ротации ключей и failover |
| **C. VPN на самом Pi** | WireGuard/AmneziaWG на Pi | автономность | **худший вариант** |

**Почему C — худший:**
- Новая подвижная часть: обрыв туннеля = робот онемел, нужен автоподъём.
- VPN добавит 20–80 мс к каждому запросу — а голосовому ассистенту важна отзывчивость.
- WireGuard Pi 5 технически потянет (Crypto Extensions, ~200–400 Мбит/с), но это лишняя работа для слабого CPU.
- Split-tunnel всё равно придётся настраивать, чтобы локальный трафик (Tailscale, SSH) шёл мимо.

**Правило:** выход меняется там, где он дешевле всего. На ПК это уже сделано и протестировано.

## 3. Как подключить Pi 5 к шлюзу

Шлюз слушает только `127.0.0.1`. Варианты — от лучшего к простому:

### 3.1 Tailscale Serve (рекомендую)

Прокси остаётся на localhost, наружу отдаётся только через tailnet — в локальную сеть не светится.

```
# на ПК
tailscale serve --bg --tcp 8317 tcp://127.0.0.1:8317
tailscale serve status
```

```
# на Pi — клиент
export OPENAI_BASE_URL="http://<имя-пк>.<tailnet>.ts.net:8317/v1"
export OPENAI_API_KEY="sk-dummy"
export BIMO_MODEL="smart"          # alias → claude-sonnet-4-5
```

### 3.2 Привязка к интерфейсу Tailscale

В `providers.json` заменить хост, **не** на `0.0.0.0`:

```json
"listen": { "host": "100.x.y.z", "port": 8317 }
```

### 3.3 SSH-туннель (без Tailscale)

```
ssh -N -L 8317:127.0.0.1:8317 user@pc
```

Минус: туннель надо держать живым (autossh).

### 3.4 Проверка с Pi

```
curl -s http://<пк>:8317/health
curl -s http://<пк>:8317/v1/models | head
curl -s http://<пк>:8317/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"smart","messages":[{"role":"user","content":"привет"}]}'
```

Заголовки `x-vibe-provider`, `x-vibe-credential`, `x-vibe-attempts` покажут, какой провайдер и ключ реально сработали.

### 3.5 Важно про условия использования

`claude-sub` работает по токенам подписки Claude Code — они предназначены для собственного CLI. Использование их из клиента-робота может нарушать условия Anthropic. **Для BIMO безопаснее провайдеры с API-ключом:** `nvidia` и `gemini`. Это стоит держать в голове.

## 4. Что реально делает Pi 5

Уточнение формулировки: с облачной моделью Pi 5 **не является процессором для модели**. Процессор и RAM модели — в датацентре. Pi 5 делает всё остальное:

| Компонент | Где | Память |
|---|---|---|
| Wake word (openWakeWord) | Pi | ~0,1 ГБ |
| VAD (Silero) | Pi | ~0,05 ГБ |
| **ASR** (whisper.cpp base) | Pi | ~0,2 ГБ |
| TTS (edge-tts, облако) | Pi — только клиент | ~0,05 ГБ |
| Agent core + шлюз | Pi | ~0,3 ГБ |
| SQLite-память (FTS5) | Pi | ~0,2 ГБ |
| Tailscale | Pi | ~0,1 ГБ |
| **Итого** | | **~1,0 ГБ** |
| Резервный локальный LLM (опционально) | Pi | +1,8 ГБ |
| **Свободно из 8 ГБ** | | **5–7 ГБ** |

**Вывод:** задача «влезет ли модель» исчезает. Более того, у вас появляется столько запаса, что можно держать **локальную модель как fallback** — на случай пропадания интернета.

**Новое узкое место — ASR.** Модель в облаке отвечает быстро (первые токены за 200–600 мс), и самым медленным звеном становится локальное распознавание речи. Что делать:
- whisper.cpp с моделью **base** или **tiny** вместо faster-whisper small — качество для коротких команд почти не падает;
- либо ASR тоже в облако (ускоренные Whisper-эндпоинты дают ответ за ~0,3 с) — но проверьте доступность из РФ;
- кэшировать распознанное, если фраза повторяется.

## 5. SD-карта на 128 ГБ

### 5.1 Ёмкости хватает с большим запасом

| Что | Размер |
|---|---|
| Raspberry Pi OS Lite 64-bit | 3–8 ГБ |
| Python + venv, зависимости | 2–4 ГБ |
| whisper.cpp base модель | ~0,15 ГБ |
| 2–3 резервных локальных LLM (Qwen3-1.7B, BitNet) | ~3,6 ГБ |
| SQLite-память + логи | 1–5 ГБ |
| **Итого** | **~12–22 ГБ** |

Остаётся **100+ ГБ свободных**. Локальные модели хранить не обязательно — но 128 ГБ дают возможность держать резерв на случай офлайна.

### 5.2 Главный риск — не место, а износ

Pi в роли голосового ассистента работает 24/7. Постоянная запись логов и SQLite убивает обычную microSD за месяцы. Обязательные меры:

| Мера | Что даёт |
|---|---|
| **Карта класса High Endurance, A2** (SanDisk Max Endurance, Samsung Pro Endurance) | рассчитана на круглосуточную запись; ~1 500–2 500 ₽ за 128 ГБ |
| **log2ram** | логи в RAM, сброс на диск раз в час → минус 1–3 ГБ записей в сутки |
| `noatime` в `/etc/fstab` | убирает запись при каждом чтении файла |
| zram-swap вместо swap на карте | убирает самый агрессивный источник записи |
| Ограничить логирование | `journald` в volatile, без постоянного хранения |
| Периодический образ карты | восстановление за 20 минут вместо пересборки |

```
# /etc/fstab — отключить запись времени доступа
PARTUUID=xxxxx-02  /  ext4  defaults,noatime  0  1
```

```
# log2ram
sudo apt install log2ram
# /etc/log2ram.conf
SIZE=128M
```

**Долгосрочно:** NVMe или USB SSD надёжнее и быстрее (см. документ 19). Но 128 ГБ High Endurance + log2ram + noatime — рабочее решение на старт.
