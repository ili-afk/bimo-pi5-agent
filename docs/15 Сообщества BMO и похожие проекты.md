## 2. Прямые попадания — кто уже сделал похожее

### 🎯 №1. Тонкий клиент с внешним мозгом — PR #17

**Автор: `jakebuild`**, май 2026. PR закрыт без слияния, **но код лежит в открытом PR**
и его можно прочитать/забрать.

Что именно он сделал — это **в точности ваша идея**:

```diff
+ "brain_type": "ollama",          // локальный мозг
+ "openclaw": {
+     "url": "http://mac-mini.ts.net:18789/v1/chat/completions",
+     "token": "your-secret-token",
+     "model": "openclaw:main"
+ }
```

- `brain_type` переключается между `ollama` (локально) и `openclaw` (удалённо).
- Удалённый мозг — **OpenAI-совместимый endpoint** с токеном.
- Доступ через **Tailscale** (`mac-mini.ts.net` — MagicDNS), то есть приватная сеть
  без проброса портов — ровно то, что я предлагал через ваш Cloudflare Worker.
- Плюс режим `--text` и условная загрузка моделей в `setup.sh`.

Есть ещё PR #18 («Thin-Client Architecture for Pi 3») и #19 («Thin client»).
Все три закрыты — автор не принял. **Но это доказательство, что направление верное
и технически реализуемое на этом коде.**

### 🎯 №2. Русский BMO — форк `tzirulnicov/be-more-agent`

**Самый близкий к вам по языку.** Русскоязычный автор, который переделал BMO под себя.

| Что изменено | Детали |
|---|---|
| **TTS** | Piper → **Silero TTS**, `v5_ru`, голос **`baya`**, 48 кГц |
| **ASR** | `whisper_lang: ru` + чёрный список фраз `["[музыка", "Редактор субтитров"]` |
| **Промпт** | «Always answer in **russian** language using the feminine gender» — ассистент говорит по-русски в женском роде |
| **Примеры команд** | «Который сейчас час?» · «Найди новости о роботах» · «Включи розетку» |
| **Умный дом** | `homeassistant_integration.py`, действия `ha_turn_on` / `ha_turn_off` |
| **Конфиг** | JSON → **YAML** (`config.yaml`) |
| **Железо** | Arduino **Nano с библиотекой Gyver EasyHID** (USB-эмуляция клавиатуры), Waveshare 5″ тачскрин, Spotpear X1002 NVMe, Waveshare UPS HAT, 18650 |

**Что это значит:** русский BMO уже существует. Технически он остался **локальным**
(Ollama + Silero + Whisper на Pi), но все «русские» решения — TTS, язык ASR, промпт,
управление устройствами — **можно брать готовыми**. Это экономит вам недели.

### 🎯 №3. Облачный мозг на ESP32 — `Zeyad-101/BMO-AI-assistant`

Студенческий проект (Египетский китайский университет, май 2026). ESP32 + MAX98357 +
OLED SSD1306 + динамик, корпус из картона.

```
Ввод в Serial Monitor → ESP32 → HTTPS POST → OpenAI GPT-4o
                              → OpenAI TTS → буфер → I2S → MAX98357 → динамик
                              + I2C → OLED (текст ответа)
```

- Задержка **1–3 с** (это подтверждает, что Г-4 «≤4 с» через облако достижимо).
- API-ключ хранится в **NVS**, не в коде.
- Arduino framework, библиотеки U8g2 / Adafruit SSD1306.

**Чего в нём нет:** голосового ввода (только текст через Serial), кодового слова, VAD.
То есть **облачная половина вашего проекта уже сделана**, а «уши» — нет.

### 🎯 №4. Устройство + внешние вычисления — `brenpoly/polymo`

**Второй проект того же автора** (сентябрь 2026, 48★, Kotlin + ESP-IDF). Архитектурно —
это ваш «Джарвис», только вычислитель — телефон, а не облако:

```
   ESP32-S3 board                        Android phone
  ┌────────────────┐                  ┌──────────────────────┐
  │  AMOLED face   │                  │  Whisper   (hearing) │
  │  mic + speaker │ ◄─── BLE ──────► │  llama.cpp (thinking)│
  │  touch         │      Opus audio  │  Piper     (voice)   │
  │  the simulation│      + protocol  │  screen-time sensor  │
  └────────────────┘                  └──────────────────────┘
```

Ключевые принципы, которые стоит перенести:

1. **«The pet owns its own life»** — состояние (симуляция) **авторитетно на устройстве**,
   хранится в NVS-flash, отсчитывается собственным RTC. Внешний вычислитель даёт только
   то, чего устройство не видит: язык, модели, датчики.
   → Для нас: **устройство держит своё состояние (сеть, батарея, индикация, кодовое слово),
   облако даёт только «ум»**.
2. **Прошивка и приложение делят один протокол** (`pet_proto.h` и `PetProtocol.kt`),
   оба объявляют версию — иначе «спарятся и будут вести себя странно».
3. **Нет разрешения `INTERNET` вообще**, и это проверяется тестом, который **ломает сборку**,
   если разрешение добавят. Механическая гарантия вместо обещания.
4. Отдельные документы: `DESIGN.md` (продукт и UX) и `CLAUDE.md` (как работать с кодом),
   и на них **ссылаются из исходников по номерам секций**.
5. Железо: Waveshare ESP32-S3 Touch AMOLED 1.8 (368×448), AXP2101 (PMIC), PCF85063 (RTC),
   поддержка двух ревизий платы с автоопределением драйвера панели (SH8601 / CO5300).

### 🔑 Два приёма, которые надо забрать у «Феникса»

1. **Гибридный ASR.** Дешёвая модель (Vosk small, 45 МБ) непрерывно слушает кодовое слово,
   а точная (Whisper) расшифровывает только саму команду. Это экономит ресурсы и деньги —
   **идеально ложится на вашу схему**: wake word локально, ASR в облако.
2. **Выбор кодового слова бенчмарком.** Автор написал `scripts/wakebench.py` и прогнал
   кандидатов: **«Феникс» распознаётся 3/3, созвучных частых слов нет**; кандидаты
   «юпитер»/«сокол» отсеялись из-за «питер»/«около». **Старое «джарвис» оставлено
   как запасной вариант.**
   → **Прямое следствие для вас: «Джарвис» — плохое кодовое слово** для русской модели,
   потому что рядом стоят «Джарвис/Джарвиса» в куче заимствований, и оно длинное.
   Методику бенчмарка стоит повторить.

## 6. Чего не делать

1. **Не строить на замороженном апстриме** — последний push 11.04.2026. Смотреть форки.
2. **Не копировать локальный стек целиком** (Ollama + whisper.cpp + Piper на Pi) — это
   путь автора, требующий Pi 5 за ~15 000 ₽. Наш путь — облако + ESP32.
3. **Не тянуть серво, Odradek, серво-руки** — это другой проект.
4. **Не надеяться на готовое русское кодовое слово** — его нет ни у кого
   (у «Феникса» wake-слово подобрано под **Vosk**, а не под WakeNet ESP32).
5. **Не считать, что «кто-то уже сделал всё»** — ни один из найденных проектов не
   соединяет вместе: **ESP32 + облачный мозг + русский язык + управление ПК**.
   Три из четырёх кубиков есть по отдельности; ваша работа — собрать их.
