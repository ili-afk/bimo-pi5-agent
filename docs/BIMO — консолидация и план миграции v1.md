# BIMO — консолидация проекта и план миграции с Raspberry Pi 5

**Дата:** 07.10.2026
**Статус:** рабочий документ. Дополняет `BIMO — полный план v3.md` (не заменяет).
**Повод:** рост цен на память (DRAM/LPDDR4X) сделал Raspberry Pi 5 16 ГБ невыгодной покупкой.
**Задача:** сохранить максимум функций при смене платформы-хоста.

---

## 0. TL;DR

1. **Вся архитектура проекта привязана не к Raspberry Pi, а к роли «хост агента».** Плата — заменяемая деталь: слои (wake word, ASR, LLM, TTS, инструменты, память, шлюз) от неё не зависят.
2. **Требование «≥16 ГБ RAM» создаёт ровно один компонент — локальная LLM (Ollama).** Всё остальное (wake word, VAD, faster-whisper `small`, Piper, инструменты, шлюз, память, Tailscale) спокойно живёт в **4–8 ГБ**.
3. **Поэтому главный ход — не «искать другую плату на 16 ГБ», а развязать LLM и хост.** Хост становится тонким (дешёвым), а «мозг» уезжает на **уже имеющийся Windows-ПК** (его память куплена до скачка цен) и/или в **уже работающий Cloudflare Worker**.
4. **Рекомендация:** тонкий хост (4–8 ГБ) + LLM на ПК/в облаке. При желании «всё локально» — **б/у SFF-десктоп или ноутбук** (DDR4, память куплена до спайка), а не новый SBC на 16 ГБ.

---

## 1. Почему миграция: что случилось с ценами

Рост цен на память в 2026 — структурный, а не сезонный:

| Факт | Значение |
|---|---|
| Рост спотовых цен DRAM, Q1 2026 | **+90 % за квартал**, ещё ~+20 % прогноз на Q2 |
| Причина | Перенос мощностей фабрик на **HBM для ИИ** (1 бит HBM «съедает» 3–4× площади пластины DDR5) |
| Реакция Raspberry Pi | **3 раунда повышения цен за 5 месяцев** (фев. 2026, апр. 2026 — третий раунд) |
| Pi 5 16 ГБ | подорожал до **≈$205**; отдельные раунды +$100 к цене модели |
| Прогноз | Улучшения **не ждут раньше 2028**, цены могут остаться на 30–50 % выше докризисных |
| Кого бьёт сильнее всего | **SBC с распаянной LPDDR** (Pi, Radxa, Orange Pi) — LPDDR4X это 30–40 % BOM |
| Парадокс | **DDR4 теперь ≥ DDR5 за гигабайт** → старая память не «дешёвый выход» |

**Вывод для проекта:** Pi 5 **16 ГБ** (распаянная LPDDR4X) — самый пострадавший вариант. Покупать его сейчас по цене, близкой к б/у x86-машине с 16–32 ГБ DDR4, экономически нерационально. Ключевой обход: **системы, чья память была закуплена до спайка** (б/у и refurb), и **снижение требования к RAM** (перенос LLM).

### 2.4. ПО и зависимости

- **ОС:** Raspberry Pi OS 64-bit (Bookworm), ARM64.
- **Рантайм:** Python 3.11+ (venv), Ollama, `faster-whisper`, `sherpa-onnx`/`openWakeWord`, `piper-tts`, `ffmpeg`, `portaudio19-dev`, `espeak-ng`, `openscad`.
- **База кода:** `tzirulnicov/be-more-agent` (русский форк) / `moorew/be-more-hailo` (веб-UI); архитектура — по образцу **Hermes Agent** (Nous Research, MIT).
- **Внешние сервисы:** Cloudflare Worker (NVIDIA/OpenRouter), edge-tts, Tailscale, Telegram Bot API.
- **ARM-специфика (риск):** колёса pip под `aarch64` для `onnxruntime`/`sherpa-onnx`/GigaAM; сборка `cua-driver` (Rust) под ARM64.

### 2.5. Ключевые технические решения

1. **Хост = обычный Linux-компьютер.** Ничего в архитектуре не завязано на Raspberry конкретно.
2. **Гибридный LLM-роутер** (локально ⇄ облако) — обязателен, не опция.
3. **Тонкий контракт с «мозгом»** — OpenAI-совместимый endpoint + токен (шаблон `brain_type` из PR #17 `jakebuild`).
4. **Управление ПК** — `computer_use` (приложения) + `terminal(ssh)` (команды/программы), не «дергать мышку» с микроконтроллера.
5. **Игры** — только Moonlight/Sunshine или виртуальный геймпад; `computer_use` игры не умеет.
6. **Удалённый доступ** — только Tailscale/WireGuard; публичный туннель к агенту = RCE.
7. **Состояние авторитетно на устройстве** (принцип из `polymo`), внешний вычислитель даёт только «ум».
8. **Тест-инвариант, ломающий сборку** (например, «нет публичного доступа к диску»).
9. **Слои заменяемы по отдельности** — именно это делает миграцию платформы дешёвой.

## 3. Что именно требует RAM (анализ)

Это ключ ко всей миграции. Разложим потребление:

| Компонент | Ориентир RAM | Можно ли убрать с хоста |
|---|---|---|
| ОС + systemd + Tailscale | ~0,5–1 ГБ | нет (но мало) |
| faster-whisper `small` (INT8) | ~1–1,5 ГБ | да → Groq (облако) |
| Piper TTS | ~0,2–0,5 ГБ | нет (дёшево) |
| openWakeWord / sherpa KWS | ~0,2–0,5 ГБ | нет (дёшево) |
| Шлюз (FastAPI + Telegram) | ~0,3–0,7 ГБ | нет |
| SQLite + FTS5 | ~0,1–0,3 ГБ | нет |
| **Ollama + Gemma 3 2B (Q4)** | **~2,5–4 ГБ** | **да → ПК / облако** |
| **Ollama + модель 7–8B (Q4)** | **~5–7 ГБ** | **да → ПК / облако** |

**Вывод:** без локальной LLM хост укладывается в **2–4 ГБ** с запасом. «16 ГБ» нужны **только** под локальный «мозг». Значит, миграция = либо (а) снять с хоста LLM, либо (б) взять платформу, где 16 ГБ стоят адекватно (б/у x86).

### 4.2. Пояснения к ключевым вариантам

**A — тонкий хост + вынесенный «мозг» (рекомендуемый).**
Хост держит голос, инструменты, шлюз, память, Tailscale; LLM вызывается по OpenAI-совместимому endpoint на ПК (Ollama) либо в облако (CF Worker). Это ровно шаблон `brain_type` из PR #17. Убирает требование «16 ГБ» полностью.

**B/D — б/у x86 SFF/mini.** Главный аргумент: их память **закуплена до спайка**, поэтому 16–32 ГБ DDR4 там идут «в комплекте» почти бесплатно. Плюс x86 = проще с Ollama, `onnxruntime`, Wine-играми. Минус — нет GPIO, но в BIMO кнопки и так на отдельном MCU (Feather 32u4), так что GPIO хосту **не нужен**.

**C — б/у ноутбук.** Самый недооценённый вариант: экран, батарея (UPS), камера, микрофон, динамик, Wi-Fi — всё в одном корпусе и уже куплено. Фактически заменяет Pi 5 + UPS-шилд X1203 + 5″ тачскрин + камеру + USB-микрофон/динамик. Минусы: габарит и износ аккумулятора.

**E — Pi 5 8 ГБ.** Если хочется остаться в экосистеме Raspberry и сохранить GPIO: 8 ГБ заметно дешевле 16 ГБ, а локальную LLM либо ограничиваем 1–2B, либо выносим на ПК/в облако.

**F — ARM-SBC.** Формально выгоднее Pi, но **те же LPDDR подорожали**, а софт сырее. Оправдано, только если нужен именно ARM + NVMe + GPIO.

### 4.3. Мини-ПК — да, можно (отдельный разбор)

**Короткий ответ: да, мини-ПК подходит и часто выгоднее Pi 5 16 ГБ.** В архитектуре мини-ПК — это ровно та же роль «хост агента» (обычный Linux-компьютер), поэтому ничего переписывать не нужно.

Есть два разных класса — важно не перепутать:

| Класс | Примеры | Память | Отношение к спайку |
|---|---|---|---|
| **Новые N100/N150** | Beelink, GMKtec, Trigkey, Minisforum | **распаяна LPDDR5** | подорожали вместе с рынком, но часто идут «комплектом» с RAM+SSD |
| **Б/у бизнес-мини** ⭐ | Dell OptiPlex Micro, Lenovo ThinkCentre M720q/M920q, HP EliteDesk 800 G4/G6 mini | **слоты SO-DIMM DDR4** (можно менять/добавлять) | **память куплена до спайка** → 16–32 ГБ почти «бесплатно» в комплекте |

**Что даёт мини-ПК:**

| Плюс | Минус |
|---|---|
| **x86-64** → проще колёса pip (`onnxruntime`, `sherpa-onnx`), проще сборка `cua-driver`, лучше Ollama | **Нет GPIO** (но в BIMO кнопки и так на отдельном MCU — не проблема) |
| 16–32 ГБ RAM без «налога на Pi» | Потребление ~10–35 Вт против ~5–12 Вт у Pi 5 |
| NVMe M.2 (в большинстве), USB 3.0, иногда 2,5G Ethernet | Может быть вентилятор (шум) — у части моделей пассивный |
| **Готовый корпус + БП** — не надо покупать NVMe Base, PSU 27 Вт, Active Cooler | Габарит чуть больше SBC |
| Б/у с SO-DIMM: RAM можно **докупить/заменить** позже | Б/у — без гарантии, проверить RAM и SSD |

**Что проверять перед покупкой:**
1. **Память распаяна или в слотах SO-DIMM?** Слоты = дешевле апгрейд и «предспайковая» память. 16 ГБ минимум.
2. **Есть ли M.2 NVMe?** Если нет — только SATA/USB-SSD (медленнее загрузка моделей).
3. **CPU:** N100/N150 — ок для тонкого хоста и моделей 1–3B; i5-8500T/9500T (б/у) — заметно быстрее и тянет 7–8B.
4. **Питание/шум:** пассивный (тихий) или вентилятор; TDP.
5. **Гарантия/продавец** (для б/у) и актуальная цена.

**Как это встаёт в проект:**
- **Один мини-ПК на 16 ГБ = и Tier 1, и Tier 2 сразу** → возвращаешься к «однокоробочной» схеме как у BIMO, но без переплаты за Pi и с x86. Самый простой переезд: `Этап 3–4` плана без «вынесенного мозга».
- **Мини-ПК на 8 ГБ** → работает как тонкий хост, а «мозг» выносится на ПК/в облако (раздел 5).
- Смета меняется в лучшую сторону: не нужны `NVMe Base` (~2–4 тыс. ₽), `PSU 27W` (~1–1,8 тыс. ₽), `Active Cooler` (~0,7–1,2 тыс. ₽) — они уже внутри.

**Вердикт:** мини-ПК — **один из двух лучших вариантов** (второй — б/у ноутбук). Если брать — приоритет **б/у бизнес-мини со слотами SO-DIMM** (Dell/Lenovo/HP) или новый N100/N150 с 16 ГБ. Pi 5 16 ГБ при текущих ценах проигрывает по соотношению «рубль за гигабайт и за функцию».

## 5. Рекомендуемая стратегия

**Двухуровневая схема «тонкий хост + вынесенный мозг» (вариант A), на железе B/C/D:**

```
┌───────────────────────────────┐        ┌──────────────────────────────┐
│  TIER 1 — тонкий хост (4–8 ГБ) │        │  TIER 2 — «мозг» (по запросу) │
│  всегда включён, ~5–15 Вт      │        │  • Windows-ПК (уже есть)      │
│                                │  LAN/  │    Ollama, крупные модели,    │
│  wake word · VAD · barge-in    │ Tail-  │    Sunshine-хост, SSH-задачи  │
│  ASR (faster-whisper small)    │ scale  │  • Cloudflare Worker →        │
│  TTS (Piper/edge-tts)          │◄──────►│    NVIDIA/OpenRouter (тяжёлое)│
│  инструменты · память · шлюз   │        │  • VseGPT.ru (резерв)         │
│  Tailscale                     │        └──────────────────────────────┘
└───────────────────────────────┘
```

- **Tier 1** — любой дешёвый хост (Pi 5 8 ГБ / Pi 4 8 ГБ / б/у тонкий клиент / мини-ПК / ноутбук). Его RAM-требование — **4 ГБ**.
- **Tier 2** — «мозг» на **уже имеющемся ПК** (память куплена до спайка) + облако. Включается по требованию; для экономии — **Wake-on-LAN** (нестандартный, но рабочий приём).
- **Роутер** уже есть в архитектуре: простое/приватное → маленькая модель на Tier 1 (или облако), тяжёлое → Tier 2.

**Почему это лучший ответ на «рост цен на RAM»:** требование к RAM у хоста падает с 16 ГБ до 4 ГБ, а дорогую память для «мозга» вы уже имеете. Спайк цен перестаёт определять выбор платформы.

**Если принципиально нужен полностью локальный «мозг» без ПК:** берите **б/у SFF/mini x86 с 16–32 ГБ DDR4** (варианты B/D) — это единственный класс, где 16 ГБ сейчас стоят адекватно.

## 6. План перехода

Каждый этап заканчивается работающим результатом.

### Этап 0. Базлайн и заморозка (0,5 дня)
- Снять «слепок» текущего хоста: список systemd-юнитов, `config.yaml`, `.env` (ключи — в защищённое место), список моделей Ollama, версии пакетов, `requirements.txt` из venv.
- Зафиксировать матрицу функций (раздел 2.6) как **критерий приёмки**.
- **Результат:** есть воспроизводимый бэкап конфигурации и чек-лист функций.

### Этап 1. Выбор пути (0,5 дня)
- Прогнать варианты A–I через таблицу 4.1 с учётом текущих цен.
- Зафиксировать: тип хоста Tier 1, нужен ли GPIO, нужен ли локальный «мозг».
- **Результат:** решение зафиксировано письменно (иначе будет дрейф, как в прошлый раз).

### Этап 2. Закупка/подготовка хоста (1–3 дня)
- Купить б/у SFF/mini/ноутбук (или взять Pi 5 8 ГБ). **Проверить:** 16 ГБ именно DDR4/наличие слотов, NVMe-разъём, состояние батареи (для ноутбука).
- **Результат:** железо на руках, тест памяти и диска пройден.

### Этап 3. ОС и паритет окружения (0,5–1 день)
- Ставить **ту же семью ОС** (Debian/RPi OS 64-bit Bookworm или Debian 12 x86-64) — минимизирует сюрпризы.
- Пакеты: `git`, `python3-venv`, `portaudio19-dev`, `ffmpeg`, `libopus0`, `espeak-ng`, `openscad`, `tailscale`.
- ⚠️ **ARM64 → x86-64:** большинство колёс станут **проще** (x86 — приоритетная платформа). Проверить `onnxruntime`, `sherpa-onnx`, сборку `cua-driver`.
- **Результат:** чистый хост с базовыми пакетами.

### Этап 4. Перенос сервисов (1–2 дня)
- Развернуть venv, скопировать конфиги/`.env`, восстановить systemd-юниты.
- Модели: либо скопировать с NVMe/SD старого хоста, либо перекачать.
- **Аудио:** заново определить устройства ALSA/PulseAudio (имена меняются!) и прописать в конфиг.
- **Результат:** голосовой цикл работает на новом хосте.

### Этап 5. Реализация «вынесенного мозга» (1–2 дня)
- Реализовать переключение `brain_type`: `local` (Ollama на ПК по LAN/Tailscale) ⇄ `cloud` (CF Worker). Шаблон — из PR #17.
- На ПК: поднять Ollama, открыть OpenAI-совместимый endpoint только в приватной сети (Tailscale), не наружу.
- Настроить роутер: простое → Tier 1/облако, тяжёлое → Tier 2.
- **Результат:** агент сам выбирает, где считать; смена «мозга» = правка конфига.

### Этап 6. Валидация по матрице функций (0,5–1 день)
- Прогнать чек-лист (раздел 7). Каждый пункт — «работает / не работает / деградация».
- **Результат:** подписанный список того, что сохранилось.

### Этап 7. Вывод старого хоста / резерв (0,5 дня)
- Старый Pi 5 либо в резерв, либо как отдельный спутник/thin-node (если 16 ГБ уже куплены).
- Обновить документацию: `BIMO — полный план v3.md`, заметки, memory.
- **Результат:** один работающий хост, документы в актуальном состоянии.

**Итого:** ~5–9 дней работы, из них критический путь — этапы 3–5.

## 8. Риски миграции

| # | Риск | Вер. | Последствие | Мера |
|---|---|---|---|---|
| 1 | ARM64 → x86-64 ломает часть зависимостей | Низкая | Стек не ставится | На x86 колёс **больше**, чем на ARM; проверить `sherpa-onnx`, `cua-driver` заранее |
| 2 | Нет GPIO на x86 | Средняя | Нельзя кнопки/датчики на хосте | Кнопки — на отдельный MCU (Feather/Arduino/ESP32), как в оригинальном BIMO |
| 3 | Имена аудиоустройств меняются | **Высокая** | Голос не работает | Переопределить ALSA/PulseAudio, зафиксировать в конфиге |
| 4 | Б/у железо без гарантии / износ | Средняя | Внезапный отказ | Тест RAM (memtest) и SSD при покупке; запасной хост |
| 5 | **Спайк RAM бьёт и по альтернативам** | Высокая | «Дешёвый» вариант тоже дорогой | Ставка на **б/у и снижение требования к RAM**, а не на новое железо |
| 6 | Вынесенный «мозг» требует включённого ПК | Средняя | Локальная LLM недоступна | Облако как фолбэк; Wake-on-LAN; автозапуск Ollama |
| 7 | Публичный доступ к агенту = RCE | Средняя | Критично | Только Tailscale/WireGuard; тест-инвариант «нет публичного доступа» |
| 8 | Облачные квоты выжигаются кодом/3D | Высокая | Ответы пропадают | Гибрид обязателен; учёт расход; резерв VseGPT.ru |
| 9 | Смена узла Tailscale / потеря доступа | Низкая | Нет удалённого доступа | Перевыпустить ключ узла; проверить до переезда |
| 10 | Потеря конфигов при переезде | Средняя | Долгая перенастройка | Бэкап на этапе 0; переносим на «холодный» диск |
| 11 | Дрейф требований в процессе | **Высокая** | Проект расползается | Фиксировать решение письменно (этап 1) |

## 9. Нестандартные подходы (явно разрешены задачей)

1. **Развязка LLM и хоста** — «мозг» на ПК/в облаке, хост тонкий. Главный приём.
2. **Wake-on-LAN для Tier 2** — большой ПК просыпается только под тяжёлую задачу.
3. **Б/у ноутбук как «тело BIMO»** — заменяет Pi + UPS-шилд + экран + камеру + микрофон + динамик одним куском.
4. **Покупка «предспайковой» памяти** — б/у машины, собранные до 2026.
5. **Гибридный ASR** — дешёвая модель ловит кодовое слово, точная расшифровывает только команду (приём из «Феникса»).
6. **Split-brain** — маленькая модель на хосте для команд/приватного, облако для тяжёлого.
7. **Старый Pi в роли спутника** — если 16 ГБ уже куплены, не выбрасывать: отдельный thin-node/резерв.
8. **Кнопки на отдельном MCU** — снимает требование GPIO у хоста, открывая x86.

## 10. Что покупать / не покупать сейчас

**Не покупать:** Raspberry Pi 5 **16 ГБ** по текущей цене — самый пострадавший от спайка вариант.
**Покупать/рассмотреть:**
- б/у SFF-десктоп или мини-ПК с **16–32 ГБ DDR4** (память до спайка);
- б/у ноутбук (экран + батарея + периферия в комплекте);
- **Pi 5 8 ГБ** — если нужны экосистема/GPIO, а «мозг» выносится;
- из нового — только если цена на 8 ГБ адекватна.

**Проверять перед оплатой:** объём и тип памяти (DDR4 vs DDR5), наличие NVMe, состояние батареи (ноутбук), продавца и гарантию, актуальную цену (рынок волатилен).
