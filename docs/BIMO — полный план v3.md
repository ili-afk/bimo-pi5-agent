# BIMO на Linux — полный план v3

**Дата:** 04.10.2026
**Статус:** смена цели проекта. Карманный «Джарвис» на ESP32 **отменён**.
**Новая цель:** Linux-агент для разных задач — код (через облако), 3D-моделирование,
удалённое управление ПК, голосовой интерфейс.

---

## 0. Что изменилось и почему

Прежний проект («Джарвис») оптимизировался под **карманный формат за 2 000–5 000 ₽**:
ESP32-S3 + xiaozhi-esp32 + облако. Ограничение «карманность» диктовало всё остальное —
дешёвый микроконтроллер, отсутствие локалки, батарея, миниатюрный корпус.

Пользователь отказался от карманности. Это меняет класс проекта:

| | Было (Джарвис) | Стало (BIMO) |
|---|---|---|
| Класс | Голосовой терминал | **Linux-компьютер с агентом** |
| Железо | ESP32-S3, ~3 000 ₽ | Raspberry Pi 5 16 ГБ, ~15 000 ₽ |
| Голос | Единственный интерфейс | Один из интерфейсов |
| Локальность | Нет (нужен интернет) | **Есть (офлайн)** |
| Задачи | Диалог, управление ПК | Код, 3D, управление ПК, диалог |

**Что сохраняется из старого проекта:**
- Cloudflare Worker (прокси NVIDIA/OpenRouter) — становится облачной половиной гибрида.
- Русский язык как основной.
- Требование бесплатности (0 ₽/мес).
- Конечный автомат, WARMUP, алиасы инструментов, Tailscale вместо проброса портов.

**Что отбрасывается полностью:**
ESP32-S3 · xiaozhi-esp32 · карманный корпус · батарея и power-path (IP5306) ·
OLED и WS2812 · русское кодовое слово на микроконтроллере · донор Яндекс Станции ·
гибридная схема «ESP32 + мини-ПК» (стала избыточной).

## 1. Ответ на вопрос «как у Hermes Agent»

Пользователь хочет архитектуру, **как у Hermes Agent**. Hermes Agent — это открытый
(лицензия **MIT**) самообучающийся агент от **Nous Research**, работающий как
**двухпроцессная система**: ядро `AIAgent` + **шлюз** (gateway) для мессенджеров.

### 1.1. Архитектура Hermes Agent (что берём)

| Слой | Как у Hermes | Что делаем мы |
|---|---|---|
| Точки входа | CLI/TUI, Desktop, Web-дашборд, Gateway (22 платформы), API-сервер, ACP | CLI + Gateway (Telegram) + Web-UI |
| Ядро | `AIAgent` — платформо-независимый, 3 режима API (chat_completions, codex_responses, anthropic_messages) | То же: OpenAI-совместимый + Cloudflare Worker |
| Реестр инструментов | `tools/registry.py`, 70+ инструментов в ~28 наборах, саморегистрация при импорте | Свой реестр, саморегистрация |
| Память | **Три слоя**: `MemoryStore` / `MemoryManager` / `MemoryProvider` + FTS5-поиск по сессиям | SQLite + FTS5 + краткосрочный контекст |
| Skills | Прогрессивное раскрытие, самоулучшение, Curator; стандарт agentskills.io | Свои `SKILL.md` |
| Терминальные бэкенды | **7 бэкендов**: local, Docker, SSH, Singularity, Modal, Daytona, Vercel | local + SSH (для ПК) |
| Голос | STT **5 провайдеров**, TTS **10 провайдеров** | Локально Whisper + Piper; облако — fallback |
| Wake word | **openWakeWord** (TFLite) / sherpa (любая фраза) / Porcupine | openWakeWord на Linux |
| MCP | `mcp_servers` в `config.yaml`, stdio + HTTP | MCP для управления ПК |
| Безопасность | `tools/approval.py`, DM-pairing, изоляция контейнеров, hard-block опасных команд | Обязательно повторить |
| Изоляция профилей | `hermes -p <name>` → свой HERMES_HOME, конфиг, память, PID шлюза | Опционально позже |

### 1.2. Управление ПК у Hermes (важно для нашей задачи)

У Hermes есть **встроенный набор `computer_use`**, который работает **в фоне**, не
перехватывая курсор и фокус клавиатуры («no-foreground contract»). Технически это
**MCP-мост к внешнему драйверу `cua-driver`** (Rust-бинарник, проект `trycua/cua`).

| Платформа | Дерево доступности | Ввод |
|---|---|---|
| Linux | **AT-SPI** (X11 + Wayland) | XTest (X11) / virtual-keyboard (Wayland) |
| Windows | UIAutomation | SendInput + PostMessage |
| macOS | AX (private SkyLight SPI) | SLPSPostEventRecordTo |

Инструменты (действия): `capture` (screenshot, `mode=som`/`mode=ax`), `click`, `type`,
`key`, `drag`, `scroll`, `focus_app`. Плюс `health_report`, `set_agent_cursor_style`.

**Безопасность (обязательно):**
- `approvals.mode: manual` — подтверждение каждого действия.
- Жёстко заблокированы: очистка корзины, force delete, блокировка экрана, log off,
  `curl | bash`, `sudo rm -rf /`, fork-бомбы.
- Агент инструктирован **не кликать диалоги разрешений** и **не вводить пароли**,
  не следовать инструкциям со скриншотов (защита от prompt-injection).
- Пароли агент вводить **не может** — только системный автозаполненитель.

### 1.3. ⚠️ Критично: игры через `computer_use` НЕ работают

У Hermes в документации прямо сказано: `computer_use` опирается на **дерево доступности**
(AX/UIA/AT-SPI). Приложения **без дерева доступности** проблемны — современные UWP,
Electron < 28, приложения с кастомной отрисовкой **и игры**. Games cited as the example
set of applications that don't expose usable accessibility trees.

**Игры через `computer_use` — не поддерживаются.** Работает только через пиксельные
координаты-фолбэк, и это ненадёжно. Это ключевое ограничение для нашего плана.

### 1.4. Что реально работает у Hermes — проверено по документации

Ты спросил: «всё остальное работает?» Проверил по официальной документации Hermes.

**Инструменты (всё это есть и работает):**

| Категория | Инструменты | Что делает |
|---|---|---|
| **Web** | `web_search`, `web_extract` | поиск в интернете, чтение страниц |
| **Терминал и файлы** | `terminal`, `process`, `read_file`, `patch` | команды, фоновые процессы, правка файлов |
| **Браузер** | `browser_navigate`, `browser_snapshot`, `browser_vision` | автоматизация браузера + **зрение** |
| **Медиа** | `vision_analyze`, `image_generate`, `text_to_speech` | анализ картинок, генерация, озвучка |
| **Оркестрация** | `todo`, `clarify`, `execute_code`, `delegate_task` | планы, уточнения, код, **подагенты** |
| **Память** | `memory`, `session_search` | долговременная память, поиск по сессиям |
| **Расписание** | `cronjob` | задачи по расписанию (создать/пауза/запустить) |
| **Интеграции** | MCP-инструменты, плагины | Home Assistant, свои серверы |

**Терминальные бэкенды — 7 штук:** `local` (по умолчанию), `docker`, **`ssh`**,
`singularity`, `modal`, `daytona`, `vercel_sandbox`.
→ **Именно `ssh` подключает твой ПК.** Тонкость: `docker` держит **один постоянный
контейнер** — пакеты и файлы в `/workspace` переживают вызовы и даже `/reset`.
Изоляция жёсткая: read-only root, все capabilities сняты, PID-лимит 256, свои namespace.

**Голос — полный набор (это важно для нас):**

| Что | Провайдеры | Ключ |
|---|---|---|
| **STT (распознавание)** | `local` (faster-whisper), `groq`, `openai`, `mistral`, `xai` | локально — **без ключа** |
| **TTS (синтез)** | `edge`, `elevenlabs`, `openai`, `neutts`, `piper`, `minimax`, `mistral`, `gemini`, `xai`, `kittentts` | `edge` и `piper` — **бесплатно** |
| **Wake word** | openWakeWord · sherpa · Porcupine | локально, **без ключа** |

**Что особенно хорошо для нашего проекта:**
- **Barge-in работает.** Микрофон живёт от конца твоей речи до конца ответа. Порог
  `barge_in_threshold_multiplier` (по умолчанию 3.0), `barge_in_grace_seconds` (0.5 с).
  **Агент получает уведомление, что его перебили** — и реагирует естественно.
- **VAD двухступенчатый** — RMS-порог 200, подтверждение 0.3 с, конец фразы после 3 с тишины.
- **Стриминг TTS** — говорит по предложениям, не дожидаясь всего ответа.
- **Фильтр галлюцинаций Whisper** — 26 известных фраз («Спасибо за просмотр» и т.п.)
  **на нескольких языках**, включая русский.
- **Русский язык поддержан:** `stt.language: ru`, стоп-фразы типа `["отбой", "стоп"]`,
  edge-tts с русскими голосами.
- **Wake word «без обучения»:** провайдер **sherpa** принимает **любую фразу** —
  просто вписываешь `phrase: "джарвис"` в конфиг. Это решает нашу старую проблему
  с отсутствием русского кодового слова!

**Что НЕ работает:**
- ❌ **Игры через `computer_use`** — только приложения с деревом доступности.
- ❌ **Wake word не работает в шлюзе мессенджеров** (Telegram) — там нет микрофона.
  Только CLI/TUI/Desktop.
- ❌ **Один микрофон за раз** — детектор отпускает микрофон на время записи.
- ❌ **Один слушатель на все поверхности** — владение «липкое», без тихого переключения.
- ⚠️ **Пароли агент вводить не может** — только системный автозаполненитель.
- ⚠️ **Настоящих требований к RAM у Hermes не заявлено** — сказано только «$5 VPS».
  Для Raspberry Pi официальной поддержки **нет**, но есть **ARM64-пакеты для
  Android/Termux** — значит ARM64 в принципе поддерживается. **Надо проверять.**

## 2. Как автор BIMO играл в игру (разбор)
В третьем видео brenpoly добавил запуск игр через **Moonlight (клиент на Pi) +
Sunshine (хост на ПК)** — стриминг игр по домашней сети. Это **не** управление игрой
через агента — это **стриминг с уже запущенной игры на ПК**, где:

- ПК рендерит игру и отправляет видео;
- Pi показывает поток и отправляет ввод обратно;
- агент лишь **запускает** процесс, а не играет сам.

**Вывод:** «BIMO играл в игру» = агент запустил Moonlight. Само управление — ручное
(или через виртуальный геймпад).

### 2.1. Если действительно нужно играть агентом

Ни `computer_use`, ни Windows-MCP этого не умеют (у Windows-MCP в документации прямо:
«can't be used to play video games»). Рабочие пути — **эмуляция геймпада на уровне ОС**:

| Инструмент | Платформа | Что делает |
|---|---|---|
| `uinput` + виртуальный Xbox-геймпад (SDL2 + ImGui) | Linux | Виртуальный геймпад на уровне ядра |
| `vgamepad` (Python) | Windows | Эмуляция XBox360 / DualShock4 |
| `node-virtual-gamepads` / `remote_gamepad` | Кроссплатформенно | Виртуальные геймпады по сети |
| Steam Input + виртуальный контроллер | Windows/Linux | Маппинг |

**Практический путь для нашей задачи:** агент **не играет**, а **запускает игру и
передаёт управление** тебе (Moonlight/Sunshine + виртуальный геймпад, если нужен ввод).

### 3.1. Ключевые решения

1. **Pi 5 — единственный хост агента.** Не «Pi + ПК как воркер» (пользователь прав:
   если ПК рядом — зачем Pi; если ПК далеко — Pi нужен сам по себе).
2. **ПК подключается через SSH-бэкенд**, а не как второй мозг. Агент запускает на ПК
   команды, программы и игры. Это модель Hermes `terminal(backend=ssh)`.
3. **Управление ПК = MCP `computer_use`** (через `cua-driver`) для приложений,
   плюс `browser` для веба, плюс `terminal(ssh)` для команд.
4. **Игры — через Moonlight/Sunshine либо виртуальный геймпад.** Не через `computer_use`.

## 5. Полный план сборки

Каждый этап заканчивается **работающим результатом**.

### Этап 0. Подготовка Pi (0.5 дня)
- Прошить **Raspberry Pi OS 64-bit (Bookworm)** на NVMe/SSD (не SD — скорость загрузки моделей).
- Обновить систему, поставить `git`, `python3-venv`, `portaudio19-dev`, `ffmpeg`,
  `libopus0`, `espeak-ng`, `openscad`.
- Включить AT-SPI (для `computer_use` позже).
- **Результат:** Pi загружается, SSH работает, базовые пакеты стоят.

### Этап 1. База BIMO — локальный голосовой цикл (2–3 дня)
- Взять базу: **`tzirulnicov/be-more-agent`** (русский форк) или живой
  **`moorew/be-more-hailo`** (но он завязан на Hailo — брать только веб-UI слой).
  Апстрим `brenpoly/be-more-agent` **заморожен** — не использовать.
- Поставить Ollama + Gemma 3, `whisper.cpp`/`faster-whisper`, Piper, openWakeWord.
- Собрать конечный автомат: `WARMUP → IDLE → LISTENING → THINKING → SPEAKING → IDLE`.
- **WARMUP** — прогрев модели (`keep_alive=-1`), иначе LLM грузится на каждый запрос.
- **Результат:** говоришь «hey jarvis» → он отвечает голосом. **Полностью локально.**

### Этап 2. Русский язык (1–2 дня)
- `whisper_lang: ru`, чёрный список фраз `["[музыка", "Редактор субтитров"]`.
- Piper `ru_RU` (ruslan/dmitri) или Silero `v5_ru`/`baya`.
- Русский системный промпт с примерами JSON-команд.
- **Прогнать бенчмарк кодового слова** (как `scripts/wakebench.py` у «Феникса»):
  «джарвис» — **плохой кандидат** (длинное, много созвучных). Проверить альтернативы.
- **Результат:** полноценный русский диалог, выбранное кодовое слово.

### Этап 3. Гибрид локально/облако (2 дня)
- Маршрутизатор: простая задача → Ollama; код/сложное → Cloudflare Worker.
- Профили моделей в конфиге (не в коде), 2–3 шт., автопереключение при ошибке.
- Ключи — в `.env` / секретах, **не в коде и не в конфиге устройства**.
- **Результат:** агент сам выбирает, где считать; смена модели = правка конфига.

### Этап 4. Инструменты (3–5 дней)
- Реестр с **саморегистрацией** (как `tools/registry.py` у Hermes).
- Белый список действий + **таблица алиасов** для галлюцинаций
  (`google/browser → search_web`, `look/see → capture_image`).
- Инструменты: время, поиск, файлы, терминал (local), код, зрение.
- **Результат:** агент ищет, читает/пишет файлы, запускает код.

### Этап 5. Код и 3D (2–3 дня)
- Code-инструменты: файлы, git, запуск компиляторов/тестов. Тяжёлое — в облако.
- **OpenSCAD/CadQuery через terminal**: агент пишет параметрический скрипт → получает STL.
- **Результат:** «сделай держатель для телефона» → получаешь `.stl` для 3D-принтера.

### Этап 6. Управление ПК (3–4 дня)
- Установить `cua-driver` и включить toolset `computer_use` (AT-SPI на Pi).
- **SSH-бэкенд терминала** → агент запускает программы и игры на ПК.
- `approvals.mode: manual` — подтверждение каждого действия.
- **Результат:** агент кликает, печатает и запускает приложения **в фоне**.

### Этап 7. Удалённый доступ (1–2 дня)
- Установить **Tailscale** на Pi, телефон и ПК. Все — в одной приватной сети.
- **⚠️ НЕ открывать публичный Cloudflare Tunnel к агенту** — это RCE. Только Tailscale
  или Cloudflare Access с аутентификацией.
- Web-UI (FastAPI) — доступ с телефона из любой точки.
- **Результат:** подключаешься к агенту с телефона, где угодно.

### Этап 8. Шлюз и безопасность (2–3 дня)
- Telegram-бот (как у Hermes), уведомления о завершении задач.
- Файл `approvals.mode: manual`, hard-block опасных команд, логирование всех вызовов.
- **Проверка инварианта тестом, ломающим сборку** (приём из `polymo`): например,
  тест, который падает, если появился публичный доступ к диску ПК.
- **Результат:** агент готов к длительной эксплуатации, действия видны и подтверждаемы.

### Этап 9. Автономность и надёжность (2 дня)
- **systemd-юнит** для автозапуска после сбоя питания.
- Watchdog, журналирование, ротация логов.
- **Результат:** Pi включился — агент уже работает.

### Этап 10 (опционально). Игры
- **Sunshine** на ПК + **Moonlight** на Pi — стриминг игр.
- Если нужен ввод от агента — виртуальный геймпад через `uinput`.
- **Результат:** играешь в игры на ПК через Pi (агент запускает, ты играешь).

### 8.4. Экономия без потери результата

- **SSD можно взять 128 ГБ** — моделям хватит; выигрыш ~1 000 ₽.

  Для первого прототипа допустимо; для постоянной работы — нет.
- **Микрофон и динамик** можно взять из старого комплекта или USB-гарнитуры.
- **Корпус** — свой, 3D-печать (это уже есть).
- Официальный БП можно заменить качественным 5 В/5 А от телефона — но Pi 5
  **требует именно 5 А**, иначе под нагрузкой будут перезагрузки.

## 9. Что нужно проверить перед сборкой

1. **Tailscale работает из РФ?** Проверить до того, как строить на нём удалённый доступ.
2. **Kодовое слово.** Прогнать бенчмарк; «джарвис» — вероятно, плохой выбор.
3. **`cua-driver` на Raspberry Pi OS (ARM64).** Собрать/скачать бинарник, проверить AT-SPI.
4. **`faster-whisper` модель `medium` на Pi 5** — реальная скорость (не только `small`).
5. **Gemma 3 1b/2b** — хватает ли для инструментов (JSON-вызовы) на русском.
6. **Публичный доступ** — убедиться, что ничего не торчит наружу (тест-инвариант).

## 10. Чего не делать

1. ❌ **Не открывать публичный туннель к агенту** — это прямой RCE.
2. ❌ Не строить на замороженном апстриме `brenpoly/be-more-agent`.
3. ❌ Не ждать, что `computer_use` будет играть в игры — только приложения.
4. ❌ Не ставить тяжёлые локальные модели в критический путь — Pi 5 слаб.
5. ❌ Не хранить ключи API в коде или в конфиге репозитория.
6. ❌ Не считать, что «всё готово» — ни один найденный проект не соединяет
   Pi 5 + русский + код + 3D + управление ПК. Кубики есть, сборка — наша работа.
